# 設計ドキュメント受け入れチェックリスト

AI が基本設計/詳細設計/API/DB 設計を生成した後、このチェックリストで確認します。

## API 設計

- [ ] すべての機能モジュールに対応する API がある
- [ ] API パスの命名規約が守られている（/api/v1/、kebab-case 複数形）
- [ ] 统一の応答形式が一貫している
- [ ] 各 API にリクエスト/レスポンス例がある
- [ ] 権限要求が明記されている
- [ ] エラー応答が定義されている（400/401/403/404/500）
- [ ] 境界ケースが考慮されている（空データ、重複送信、並行など）

## DB 設計

- [ ] すべての API が必要とするフィールドが表に存在する
- [ ] テーブル名/カラム名が snake_case 規約に従っている
- [ ] 主キー/外部キー/インデックスが定義されている
- [ ] 関連が正しい（一対多、多対多）
- [ ] created_at 等の共通フィールドが含まれている
- [ ] マイグレーション順序が妥当で、循環依存がない

## 画面設計

- [ ] すべての機能モジュールに対応する画面がある
- [ ] 画面パスがディレクトリ構成規約と一致する
- [ ] 入力項目に型、バリデーション、デフォルト値がある
- [ ] 操作ボタンが明確なアクションと遷移を持つ
- [ ] 権限制御が明記されている

## 一貫性

- [ ] API のフィールドが DB のカラム名と対応している
- [ ] 画面表示データが API 応答と対応している
- [ ] 権限マトリクスが役割定義と一致している
- [ ] 状態遷移が API と DB で一致している

## 人の確認項目

- [ ] API 契約の確定（多人数協業の契約）
- [ ] DB スキーマ確定（指定開発者がマイグレーションを実行）
- [ ] 権限モデルの最終確認
- [ ] 例外処理戦略の最終確認
