# 要件ドキュメント受け入れチェックリスト

AI が要件ドキュメントを生成した後、このチェックリストで確認します。

## 完全性

- [ ] システム概要は明確で、1 文でシステムの説明ができる
- [ ] ユーザーの役割がすべて定義されており、典型操作が含まれる
- [ ] 機能モジュールがすべて列挙されており、漏れがない
- [ ] データモデルに主要なテーブルと主要フィールドが含まれている
- [ ] 開発フェーズの分割が妥当で、依存関係と評価（根拠）が説明されている
- [ ] 既存システムとの関係が説明されている
- [ ] 技術方針が確定している

## 一貫性

- [ ] 役割の権限が、各モジュールの説明で一致している
- [ ] データモデルのフィールドが機能説明と対応している
- [ ] 状態遷移が完全で、死ループや欠落状態がない
- [ ] API / 画面 / データ表が相互に対応できる

## 実現可能性

- [ ] 各機能モジュールに明確な入力と出力がある
- [ ] 要件が曖昧すぎない（「など」「適当」等の未定義語がない）
- [ ] 技術選定がチームの能力と整合している
- [ ] 開発フェーズの作業量見積もりが妥当

## 未決事項

- [ ] 「未定」項目がすべて列挙されている
- [ ] 人の確認が必要な点が明示されている
- [ ] リスクが識別されている

## 人の確認項目（必須）

以下は必ず人が確認し、AI 出力だけに依存しない：

- [ ] 要件範囲（やること/やらないこと）
- [ ] ユーザー役割と権限
- [ ] OA/外部システムとの連携方式
- [ ] 開発フェーズの分割と担当者の割り当て
